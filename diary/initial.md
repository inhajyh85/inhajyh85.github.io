# 일기장 — MVP 설계서

## 1. MVP 목표
브라우저만으로 쓰는 **개인 일기장**. 달력에서 날짜를 고르고, 그날의 **감정 이모티콘**과 함께 일기를 쓰고, 고치고, 지우고, 다시 찾아볼 수 있다.

- 형태: **HTML 파일 1개** (HTML + CSS + JavaScript)
- 서버: **없음** (GitHub Pages에 그대로 배포)
- 저장: 브라우저 **localStorage** (로그인·DB 불필요)
- 비용: **0원**

## 2. 기능 목록
| 기능 | 설명 |
|---|---|
| 작성 | 날짜(기본 오늘) · 감정 · 제목 · 본문 입력 후 저장 |
| 수정 | 상세 화면에서 [수정] → 같은 작성 폼에 기존 내용 채워서 편집 |
| 삭제 | 상세 화면에서 [삭제] → `confirm()` 확인 후 삭제 |
| 날짜별 관리 | 월 달력에 일기가 있는 날은 **감정 이모지**로 표시. 날짜 클릭 → 그날 일기 목록 |
| 조회 | 선택한 월/날짜의 목록, 항목 클릭 → 상세 보기. 제목·본문 **키워드 검색** |
| 감정 선택 | 6가지 중 하나 선택 (필수) |
| 내보내기 | 전체 일기를 **JSON 파일**로 다운로드 (백업·기기 이전용) |
| 불러오기 | 내보낸 JSON 파일을 골라 **합치기** 또는 **모두 바꾸기** |

- 하루에 일기를 **여러 개** 쓸 수 있다 (같은 날짜에 여러 항목, 작성 시각순 정렬).
- 미래 날짜도 막지 않는다 (계획·메모용).

## 3. 데이터 구조 (localStorage)
- 키: `diary.entries` → 일기 배열을 JSON 문자열로 저장
```json
[
  {
    "id": "lz3k9a-x81f",
    "date": "2026-11-08",
    "mood": "happy",
    "title": "첫 일기",
    "content": "오늘은 일기장을 만들었다.",
    "createdAt": 1762588800000,
    "updatedAt": 1762588800000
  }
]
```
- `date`는 사용자가 고른 날짜(`YYYY-MM-DD`, 로컬 시간 기준), `createdAt/updatedAt`은 ms 타임스탬프
- `id`는 `Date.now().toString(36) + 랜덤` 으로 생성
- 테마 선택은 루트 페이지와 같은 키 `theme`(`light`/`dark`)를 공유
- 모든 localStorage 접근은 `try/catch`로 감싼다. 사용할 수 없으면(사생활 보호 모드 등) **메모리에만 저장**하고 "새로고침하면 사라집니다" 경고 배너 표시
- 용량 초과(`QuotaExceededError`) 시 저장 실패 안내

### 3-1. 내보내기/불러오기 파일 형식
- 파일 이름: `diary-backup-YYYY-MM-DD.json` (내보낸 날짜)
```json
{
  "app": "diary",
  "version": 1,
  "exportedAt": "2026-11-08T17:30:00.000Z",
  "count": 6,
  "entries": [ { "id": "...", "date": "2026-11-08", "mood": "happy", "title": "...", "content": "...", "createdAt": 0, "updatedAt": 0 } ]
}
```
- 내보내기: `Blob` + `URL.createObjectURL` + `<a download>` 로 브라우저에서 바로 저장 (서버 불필요). 일기가 0개면 안내만 표시
- 불러오기: `<input type="file" accept=".json">` + `File.text()` → `JSON.parse`
  - 위 형식의 객체 또는 **일기 배열만 있는 JSON**도 허용
  - 항목별 검증·정리: `date`가 올바른 `YYYY-MM-DD`가 아니면 버림 / 알 수 없는 `mood`는 `soso` / `title`·`content`는 문자열로 / `id`·시각이 없으면 새로 생성 / 제목·본문 모두 비면 버림
  - 유효한 일기가 0개거나 파일이 5MB를 넘으면 오류 안내
- 불러오기 방식 (현재 일기가 있을 때 선택 대화상자, 없으면 바로 불러옴):
  - **합치기**: `id`가 같은 일기는 `updatedAt`이 더 최근인 쪽을 남기고, 없는 일기는 추가 → "추가 N개 · 갱신 N개 · 그대로 N개" 안내
  - **모두 바꾸기**: 현재 일기를 지우고 파일 내용으로 교체 (되돌릴 수 없다는 경고 표시)
- 저장 실패(용량 초과) 시 불러오기 전 상태로 되돌림

## 5. 동작 흐름
1. 페이지 열림 → localStorage에서 일기 불러오기 → 이번 달 달력 + 오늘 날짜 선택
2. 달력 날짜 클릭 → 선택 날짜 변경 → 그날 목록 표시 (같은 날짜 다시 클릭 → 선택 해제, 월 전체 목록)
3. [새 일기] → 작성 폼 (날짜 = 선택 날짜 또는 오늘). 저장 시 검증: 감정 필수, 제목 또는 본문 중 하나 이상
4. 저장/수정/삭제 → 배열 갱신 → localStorage 저장 → 달력·목록·통계 다시 그리기
5. 작성 중 [취소] 시 입력 내용이 있으면 버리기 전에 확인
6. 단축키: 작성 폼에서 `Ctrl+Enter` 저장, `Esc` 취소
7. [내보내기] → JSON 파일 다운로드 / [불러오기] → 파일 선택 → 검증 → (합치기·모두 바꾸기 선택) → 저장 → 다시 그리기

## 6. 핵심 코드 뼈대
```html
<script>
const KEY = 'diary.entries';
let entries = loadEntries();

function loadEntries() {
  try { return JSON.parse(localStorage.getItem(KEY)) || []; }
  catch (e) { return []; }
}
function saveEntries() {
  try { localStorage.setItem(KEY, JSON.stringify(entries)); return true; }
  catch (e) { return false; }   // 저장 불가 → 경고 표시
}

const pad = (n) => String(n).padStart(2, '0');
const ymd = (d) => `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}`; // 로컬 날짜

function upsert(entry) {
  const i = entries.findIndex((e) => e.id === entry.id);
  if (i >= 0) entries[i] = { ...entries[i], ...entry, updatedAt: Date.now() };
  else entries.push({ ...entry, id: newId(), createdAt: Date.now(), updatedAt: Date.now() });
  saveEntries(); renderAll();
}
function remove(id) {
  entries = entries.filter((e) => e.id !== id);
  saveEntries(); renderAll();
}
</script>
```
- 본문 출력은 `textContent` 사용 (사용자 입력을 `innerHTML`로 넣지 않음), 줄바꿈은 CSS `white-space: pre-wrap`

## 8. 알아둘 한계 & 다음 단계
- **localStorage는 이 브라우저·이 기기에만** 저장됨. 다른 기기와 동기화 안 되고, 브라우저 데이터 삭제 시 사라짐. 용량은 보통 출처당 약 5MB(텍스트 일기 수천 개 수준).
- **암호화 없음**: 같은 컴퓨터를 쓰는 사람은 개발자 도구로 볼 수 있음.
- **다음 단계 아이디어**
  - 내보낸 백업 파일은 **암호화되지 않은 평문**이므로 보관에 주의
  - 비밀번호 잠금(Web Crypto로 본문 암호화)
  - 사진 첨부(IndexedDB), 태그, 감정 그래프(월별 추이)
  - 클라우드 동기화가 필요해지면 서버/백엔드(예: Supabase) 필요 → MVP에서는 제외
